# 1.15.0 — correctness round after 1.14.0

**Status:** implemented, measured, shipped. **Date:** 2026-10-15. Release commit `ed771d8`.

No rule was added and no threshold was retuned. 30 rule IDs, 21 analysers, **713 tests** — the same
catalogue as 1.14.0. This release collects the four follow-ups to 1.14.0 that were committed as work
in progress after the tag, plus one hygiene change the self-scan found in its own new code.

Three of the four change what Snipper *reports*, so the upgrade table in [`usage.md`](../usage.md)
carries a row for each. All four were measured on the reference monorepo (MILKRUN) with the same
flags on both sides.

## What shipped

Oldest first.

### 1. Complexity rules skip test code (`d06421f`)

`ExclusionEngine.IsTestCode(filePath, projectName)`, consulted by SNP0033 and SNP0034 **after**
`ShouldSkipDocument`.

It is deliberately a *second* predicate rather than a fourth arm of the first. `ShouldSkipDocument`
stays test-code-neutral: a private member that is genuinely dead is just as dead in a test project, so
the reference-checking rules still analyse test code. One gate and two decisions means relaxing
either cannot silently relax the other.

A document is test code when:

- a **directory** segment is exactly `test` or `tests`, case-insensitively — the file name is
  excluded, so a production file called `MyTests.cs` is production code; or
- the project's final dotted segment is exactly `Test` or ends with `Tests`.

Matching is on whole segments, never substrings, so `Contest`, `Testing` and `Latest` all stay in
scope. Threshold, reason, rule ID and source position are unaffected: the document is skipped, not
downgraded.

**Measured:** 2,466 → 2,464 across three interleaved rounds, 0 added, +17 tests. The two removed
findings are SNP0033 and SNP0034 on the same `Doubles.cs` fixture. This is a small number and is
reported as one. The change earns its place by removing the single worst finding in the report and by
protecting repositories whose fixtures are heavier — not by clearing a queue on this one.

**Consequence for release arithmetic:** 1.14.0 shipped 80 raw SNP0034 findings. A default run
reports **79 SNP0034 and 41 SNP0033**.

### 2. SNP0031 names its copies by workspace-relative path (`3516ab9`)

SNP0031's message carried **absolute** paths, and the fingerprint is `RuleId|path|Message` hashed
verbatim. So every SNP0031 fingerprint depended on where the repository happened to be checked out: a
baseline committed on one machine reported every SNP0031 finding as new on another.

SNP0032 already had this right (`CloneDriftDetector.ToRepositoryRelative`); SNP0031 did not, so the
report contradicted itself between two rules that run together. Four tests, each confirmed red
before the fix.

**Measured:** 3,790 → 3,790 total, SNP0031 1,131 → 1,131, SNP0032 195 → 195, every SNP0031 anchor at
the same path and line, and **0 of 1,131** messages still contain a drive path. SNP0032 byte-identical.
706 → 710 tests.

**Re-baseline**, for the same reason as 1.9.0 / 1.10.0 / 1.13.0: a message change re-fingerprints
without changing a single finding.

### 3. Shape-collision clone sets: measured, guard rejected (`50398f5`)

**No code change.** The 1.12.0 note deferred a suppression guard on "shape-collision" clone sets
because two examples cannot calibrate one. All 1,131 SNP0031 sets on the reference monorepo have now
been classified, so the guard could be tested rather than assumed.

| Clone-set shape | Sets | Share |
| --- | --- | --- |
| Contains a method body | 535 | 47.3% |
| Declarations, unclassified | 230 | 20.3% |
| `const` / enum table | 193 | 17.1% |
| DTO property bag | 173 | 15.3% |
| **Declaration-only total** | **596** | **52.7%** |

More than half of SNP0031's output is declaration-only, and 65% of DTO property-bag pairs share no
identifier at all.

The candidate guard was **property-name overlap**. Token normalisation discards every identifier, so
`public string? Name { get; init; }` matches whatever it is a property of — the guard was the
obvious answer and it was wrong. It would also remove genuine Type-2 rename-only clones
(`Metro60ExtendedProductAttributeDefinitions` ↔ `WoolworthsProductAttributeDefinitions`, real
per-brand schema duplication), which is the feature SNP0031 advertises. Measured, then **rejected**.

The right outcome was to record that, not to ship a guard that trades the feature for a quieter
report. The finding it was meant to suppress is still reported — by 4C instead, below.

### 4. 4C caps a peer it cannot demonstrate (`4772174`)

Follows the calibration in (3). SNP0032 asserts "an equivalent change reached the sibling later",
which claims two regions are *the same code*. Normalisation cannot support that claim when the set
is declaration-only and shares no identifier with the anchor: token-identity is then the only evidence,
and it is evidence about shape, not meaning.

`RegionEvidence` collects identifiers by line plus the lines carrying a statement, arrow expression or
invocation, in a second pass that runs **only** under `--clone-drift`. `CloneSet.MembersComparable`
is false only when *every* member's region is declaration-only **and** no member shares an identifier
with the anchor.

Both halves of that conjunction are required, and this is the non-obvious part:

- **Identifier-disjointness alone** would reject genuine Type-2 method clones — the guard rejected in
  (3), in a different place.
- **Declaration-onlyness alone** would reject any two identically-shaped configuration classes.
- **Missing evidence returns comparable**, so the verdict never depends on which flags were passed.

An incomparable set is capped at **Advisory** however fix-shaped its text reads. The finding is
**kept, not dropped**, and carries a caveat naming what is missing (`ComparabilityCaveat`, the same
move 1.11.0 made).

**Measured:** 3,790 → 3,790 total, SNP0032 `High` 6 → 5, `Advisory` 189 → 190, 38 findings carrying
the caveat. `IOrderApi.cs` is demoted; `UpdateCustomerRequest.cs` stays `High` because its set
includes a method body. Self gate 84 known / 0 new, baseline 83 → 82 fingerprints. 710 → 713 tests.

### 5. Drop `SnipperFinding.Symbol` (`ed771d8`)

The `ISymbol` on every finding was written at 17 sites and read at none. It was the only Roslyn type
in `Models`, and it made record equality compare a Roslyn object. Removing it touches only call
sites; the report, fingerprints and baseline are unchanged.

Two consequences found on the way:

- `RedundantQualifierEvaluator.CreateFinding` lost the parameter that existed only to feed `Symbol`.
  Caught by the self-scan as an SNP0010 unused-parameter finding — the tool found its own dead
  parameter.
- A `CliRunner.fingerprintMemo` comment claimed distinct findings could compare equal and be given the
  wrong fingerprint. That was false: the fingerprint is a function of the fields record equality
  compares, so it could not happen. Reference keying stays, because it is cheaper.

### 6. Build hygiene and a self-check in CI (`935799b`)

Formatting gates, plus a CI step that runs Snipper against its own repository against the committed
baseline. That gate is what surfaced (5)'s unused parameter, and it is the gate that
[1.16.0](../1_16_0_plan.md) later reports as failing against a baseline last refreshed before 1.15.0.

## Behaviour changes, and what they cost a baseline

| Change | Baseline effect |
| --- | --- |
| SNP0033/SNP0034 skip test code. | **Findings removed, no re-baseline.** Exactly 2 of the 80 new SNP0034 findings, both on one `Doubles.cs` fixture. |
| SNP0031 names copies by workspace-relative path. | **Re-baseline.** 1,131 → 1,131; the message is fingerprinted verbatim. Same as 1.9.0 / 1.10.0 / 1.13.0. |
| SNP0032 gains a comparability caveat and a tier cap. | **Re-baseline if you run `--clone-drift`.** Tier and message change; the count does not. 3,790 → 3,790, `High` 6 → 5. |
| `SnipperFinding.Symbol` dropped. | None. Internal only. |

All four land in this release, and two of them are message-only changes on
`--duplicate-detection` runs. That is the worst case for a baseline: finding counts barely move
while fingerprints churn, so a count-based gate sees nothing and a "new findings" gate sees
everything at once.
